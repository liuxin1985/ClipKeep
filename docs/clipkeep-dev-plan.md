# ClipKeep 开源浏览器插件开发与涨星规划

## 项目定位

跨 Chrome、Edge、Safari 的轻量划词收藏插件，纯前端离线运行，无后端无账号。
学生整理网课重点、上班族留存周报素材都能用，主打**一键划词存本地、导出 Markdown、净化网页阅读**。

## 核心功能清单（v1.0 已完成）

1. 划词监听 + 浮动工具条，点击收藏到 `storage.local`。
2. 快速收藏卡片：支持备注、标签。
3. 右键菜单：收藏选中内容 / 净化阅读本页。
4. 极简列表弹窗：展示已存内容、搜索、排序、标签筛选。
5. Markdown 导出：单条 + 批量。
6. 净化阅读模式：移除广告 / 侧边栏 / 导航，只留正文，可收藏全文。
7. 标签分类、深色模式、一键复制单条。

## 核心功能清单（v1.1 已完成）

8. 划词高亮：四色涂色，落盘后可跨标签页同步，重开页面按文本自动重放。
9. 原文批注：粉色高亮 + 悬停显示，点击高亮可改可删。
10. 每日回顾：Leitner 六盒间隔重复（0/1/3/7/21/90 天），待回顾红点徽标。
11. JSON 备份 / 恢复：收藏 + 高亮单文件导出，按 id 幂等合并。
12. 自动化测试：jsdom 直跑真实代码，58 → 132 项断言，`npm test` 一条命令。

## 核心功能清单（v1.10 已完成）

61. 跨节点高亮锚定：一条高亮按文本节点拆成 `segs: [{ t, pre, post }]`，每段带前后各 24 字上下文；
    重放时按段序（后一段必须落在更靠后的节点）逐段定位，再把跨过的正文拼回来与原文核对，
    对不上就换下一处出现重试（封顶 8 次护住长页面），任何一段找不到则整条放弃——宁可不标也不标满页。
62. 锚点与正文自洽：入库前要求 `join(segs.t) === text`（后台 `cleanSegs` 是唯一的尺子），
    正文被 20000 字上限砍短时锚点跟着砍齐而不是整份作废；DOM 走查摸到 `display:none` 这类
    浏览器划选不认的字时，整份丢掉锚点退回可见正文，不把用户没见过的字写进正文。
63. 跨元素选区的正文不再丢空格：词间的空白节点是正文的一部分（`Hello␠world` 不能存成 `Helloworld`），
    只掐头去尾丢掉纯空白；`splitText(0)` 不再留下空文本节点。
64. 提示跟着能力走：锚定成功不再保留「跨元素可能不显示」的话术，退回整段查找时才说；
    正文被截断时当场报「已高亮（正文超过 20000 字，已截断）」而不是「已高亮 ✓」。

    页面浮层在偏好变化那一次拆掉缓存重建、已有高亮的批注提示重放一遍换语言（开着且有输入的卡片与阅读层不动，
    不丢用户正在打的字），右键菜单只在「解析后的语言真的变了」时重建，导出的 Markdown 抬头跟着换。
67. 文案层的三条硬规矩，都由断言钉住：**整句而不是词块**（把「收藏 / 高亮」塞进句子，英文就成了
    `Clip / Highlight wasn't written`）；**模块级常量只存 msgid**（`const X = T("…")` 会在读到偏好之前
    就把语言冻住，翻译要发生在用的那一刻——源码扫一遍就报，扫法本身先用一段含两种合法写法的样例钉住，
    免得检不出东西的检查当成功）；**不碰宿主页面**（内容脚本只改自己浮层的文字，
    改人家的 `<html lang>` 会让整页朗读和字体都跟着错）。语言名按该语言本身书写（`中文` 这一项永远不翻译）。
68. 缺条与死词条都逃不掉：英文词典覆盖全部 msgid、占位符数量两边一致、词典里不许留源码已不再用的条目、
    没有 `i18n.js` 时（老的抓帧桩、直接 eval 的页面）界面退回中文而不是报错。
69. 文档级上下文锚定：捕获与解析两端统一走「整页文字 + 每个节点起点」的扁平索引，
    24 字上下文窗口可以越过节点边界向邻居借字——选区正好盖住一整个文本节点时（只划一个 `<strong>猫</strong>`），
    页面上有两处同名文本，标的也是用户划过的那一处，不再是第一处。
70. 相邻两段的判定从「必须分处两个节点」放宽为「在整页文字里挨着」，页面上被重排成一个节点的高亮也能拼回来；
    旧记录的空上下文照旧按 `indexOf` 兼容处理。
8. **守规矩的检查也要先证明它会报**：「模块级常量不许存译死的文案」这条是靠正则扫源码，
   第一版少写了一个空格和 `_`，三个真实文件全过——看着像「没人违规」，其实是检查根本没在工作。
   同一条断言里先塞一段样例（两条该报、三条不该报），扫不到样例就当场红。
9. **缩略图里「靠边」不等于「被挤出」**：出完演示帧我盯着 380px 的缩略图，认定工具条最右的 🏷
   被裁掉一半，顺手写了三行 flex 修补加三条断言。拿真浏览器量一遍：按钮落在 336–366px，弹窗 380px，
   中英文都在里面，页面横向也没溢出（`scrollWidth === clientWidth`）。改动全部回滚。
   布局问题要么量出像素再说，要么别说它存在——而 jsdom 不排版，这类断言只能守声明，守不住「到底挤不挤」。
10. **同一轮目测，一次看走眼、一次看漏**：上面那条是看走眼；紧接着在旧动图里发现 ⑪⑫⑬ 从 v1.9 起
   就是四个豆腐块（主字体只画到 ⑩），这才是真该修的。两个教训合起来是同一条：
   截图要 1:1 放大逐帧看，看完还要能说出像素数或字形名，否则「看着不对」和「看着没事」都不作数。

71. 数据自检面板（⚙ 设置里）：收藏 / 高亮 / 回收站条数、数据大小与浏览器报的占用与配额、

## 技术选型

- **Manifest V3**（Chrome / Edge）+ Safari 16.4+ 适配层。
- 原生 JavaScript，无框架、无构建工具。
- 存储：`chrome.storage.local` / `browser.storage.local`。
- 高亮重放：`Range.surroundContents` + `TreeWalker` 文本匹配（无坐标依赖，抗排版变化）。
- 回顾调度：Leitner 盒 + `due` 时间戳，字段内嵌在收藏项里，天然随备份走。
- UI：手写 CSS，清爽卡片风（避免 MV3 CSP 对 CDN 的限制）。
- 跨浏览器适配：`const API = browser || chrome` 统一入口。
- 测试：jsdom（仅 devDependency，扩展产物零依赖）。

1. **筛选要按「库实际上有什么」生成**：类型与站点 chip 由当前数据算出来，只有一种类型且只有一个站点时
   整条筛选条不出现；数据变了就剪掉已经不存在的选项——摆一个点不出东西的控件，比没有控件更糟。
2. **筛完的提示必须说人话**：库里明明有货却报「还没有收藏」是提示说谎，改成「筛选后没有结果」。
3. **键盘流复用鼠标那条路**：`x` 勾选取决于 `toggleSelect`、`Enter` 直接点行内的展开按钮，

4. **整条重绘会吃掉焦点**：chip 用 `innerHTML` 重绘后必须把焦点放回原来那个，否则键盘用户从头再 Tab 一遍。

**提交记录：** 2026-10-02 两项功能 + 7 类缺陷修复 + 742→854 项断言 + 文档同步，版本号升到 1.8.0。
三条经验：
1. **「成功」要按真实后果定义**：`delete` 对不在册的 id 返回 `ok` 本身就是在撒谎——它什么都没删、
   也没进回收站，前端据此说的每一句「可撤销」都是空话。写入类消息的成败口径统一成「存储是否真的变了」。
2. **计数要只算真发生的**：撤销整批时 `restored` 把撞 id 没回来的几条也算进去，覆盖失败时照报待写条数——
   数字看着合理，用户却会在这些数字上做出「不用再来一遍」的判断。
3. **成功的提示也要带上不完整**：截断是后台正常完成的一次写入，`ok` 为真，但「已收藏 ✓」并不等于「剪全了」。
   凡是结果与用户预期可能不一致的正常路径（重复、截断、上限），都值得一句明确的话术。

### 12. v1.9 重叠与逐条（让「多标一层」和「误删一条」都不再靠运气）
1. **重叠区间要按边界切开，不是「后者覆盖前者」**：同一段话先标一句、再标包住它的整段是最常见的用法，
   旧写法把区间当互不相交处理，交集那段只剩一层，用户以为两条都在。分段渲染（ outer 边界 + 段内包裹）
   让两条各自可见，代价是一条高亮会拆成多个片段——于是撤销必须按「同一条」而不是「同一个节点」来。
2. **整批撤销不够用**：回收站只有「全回来 / 全不回来」时，误删一条只能连带还原九条，实际等于没有撤销。
   明细 + 逐条恢复才是可操作的粒度，且按钮文案要写清它只管哪一批。
3. **过期口径必须一致**：整批撤销不先清过期，弹窗开着不动就能让早该消失的条目复活——两条路径同一份数据，
   任何一步少做同样的清理，都会变成数据上的矛盾。

**提交记录：** 2026-10-03 两项功能 + 本轮审计 12 类缺陷修复 + 854→985 项断言 + 文档同步，版本号升到 1.9.0。
五条经验：
1. **上限要说舍弃数，成功也要说不完整**：`TAG_MAX = 12` 之外的标签被后台丢弃，`ok` 为真，
   但只报「标签已更新」用户听不出少存了几个。凡是「做了但没全做」的路径都值得一句明确话术。
2. **附属写排在主键之后**：回收站条目 / 打卡计数和主数据是同一次操作的产物，写在主键前面一旦失败，
   就留下「收藏没了、回收站里却躺着一条没删掉的」这种半更新——比整体失败更难被发现。
3. **身份键不能用在写入时现生成的 id**：备份里的非法 id 会被清洗成新的，拿 id 去比「是不是同一条」
   等于每条都是新的，同一份备份导第二次高亮直接翻倍。身份要按内容（地址 + 正文 + 落点时间）认。
4. **承诺的范围要和代码的作用域一致**：确认框写了「高亮批注不受影响」，实现却把整个回收站清空——
   文案改了 `kind`，函数却没跟上。清空类操作一律按类别过滤，别顺手做全量。
5. **做不到的事先说别做**：跨元素选区（选段里带 `<strong>`）刷新后重放不回来，本版没有伪造锚定，
   而是把提示改成「已高亮（跨元素，刷新后可能不显示）」，并把这个已知限制写成断言钉住，真正的锚定留给 v1.10。

### 13. v1.10 跨节点锚定（把上一版「诚实标注的限制」真正消掉）
1. **锚点要带上下文，还要带顺序**：只按文本匹配的话，一句重复出现三次就会标到第一处；分段锚点加上
   「后一段必须落在更靠后的节点」和「跨过的正文拼回来必须等于原文」两道校验，才敢在长页面上下锚。
   校验不过就换下一处出现重试（`ANCHOR_RETRY = 8` 封顶），全部落完仍对不上则整条不标——
   把一条高亮劈成满页，比刷新后看不见更难解释。
2. **锚点必须与正文自洽**：`join(segs.t) === text` 这条不变式一旦破了，重放就会去标别的字。
   所以后台 `cleanSegs` 对不上就整份作废（退回单段整词查找），正文被 `MAX_TEXT` 砍短时锚点跟着砍齐
   而不是作废——截断是正常写入，不该顺手废掉定位能力。
3. **能摸到的字不等于用户选中的字**：真浏览器审计抓到 `display:none` 的文本会被 DOM 走查切进锚点，
   而 Chrome 的 `Selection.toString()` 不认它们——正文里凭空多出一排用户没见过的字。
   jsdom 两边口径一致，这条在测试里复现不出来，只能靠真浏览器跑一遍；守卫是拼不回可见正文就丢掉锚点。
4. **空白是正文，不是排版**：为了「段间拼接正好等于正文」而顺手丢掉空白节点，会把
   `Hello world` 存成 `Helloworld`。只该掐头去尾丢纯空白，中间那个空格得留着。

### 14. v1.11 英文界面 + 借得到的上下文
1. **msgid 就用中文原文**：真要给每条文案起一个 `save_clip_toast` 这样的名字，就得同时维护
   「名字 → 中文」和「名字 → 英文」两张表，而中文那条一丢，界面直接空一半。用中文原文当 key，
   zh 是恒等映射、en 查一张扁平表，缺一条就退回中文并在断言里报出来——**漏翻译不会白屏，只会露出来**。
2. **模块级常量只许存 msgid**：`const TITLE = T("设置")` 在脚本加载时就把语言钉死了，
   用户换偏好之后这句永远不变。改成常量存原文、用的时候再 `T()`。
   同类问题还有「建一次就缓存的 DOM」：工具条和卡片要在语言变更时拆掉重建，
   但卡片正被人打着字（`display: block`）就不拆——丢用户的字比少一次翻译严重。
3. **翻译整句，不翻词块**：把「收藏 / 高亮」这种词块塞进另一句，英文就成了
   "Clip / Highlight wasn't written"——两个名词配单数动词、还在句中大写。
   覆盖失败的三种情况各配一整句译文，语法归文案层，拼装归代码。
4. **译名要跟着源码逐条对**：275 条译文与源码里的 msgid 双向核对，缺条（源码有、表里没有）
   和死词条（表里有、源码已删）都算缺陷。这条只能写成断言，靠人眼扫一遍必然漏。
5. **写 aria 得用 `setAttribute`**：`el["aria-label"] = x` 只是在 JS 对象上挂了个属性，
   DOM 上的 `aria-label` 一个字没变，屏幕阅读器读不到——`aria-*` 没有同名 property，属性名必须走属性写。
6. **冷启动读偏好失败不能把兜底语言钉死**：服务 worker 醒来第一件事是定语言，那次 `get` 失败
   只说明「这一回没读着」，用户存的偏好还在。原来兜住异常就把语言定成浏览器语言再缓存住，
   英文界面要等用户下次改偏好才有机会纠正。现在失败不缓存、由调用方补读一次（只补一次，
   存储一直坏就不许无限重试），而 `onInstalled` 可能正好挂在那条失败的 in-flight promise 上，
   所以补读要重新起一次，不能只等旧的。
7. **文档级上下文锚定**：选区正好盖住整个文本节点时，段内上下文是空的，重复短词只能落在第一处。
   捕获与解析两端统一改成「整页文字 + 每个节点起点」的扁平索引，上下文向邻居借字（各 24 字），
   相邻两段的判定也从「必须分处两个节点」放宽为「在整页文字里挨着」——
   旧记录没有文档级上下文的照旧按节点内匹配，行为与 v1.10 一致。

### 15. v1.12 心里有数（把「好像存进去了」变成「现在到底怎么样」）
1. **自检不许拿快照当真**：弹窗里的 `items` 是打开那一刻读回来的，放着不动能挂好几分钟。
   面板每一次都重新读五个键、重新算一遍，「重新自检」就是再走一次这条路。
   读失败时整块面板换成一句「存储读不到，自检没跑成」——**留着一屏旧数字，比说没算成更像出了 bug**。
2. **只读是自检的底线**：页面那一行问的是当前标签页里的内容脚本，重放用 `pageFlat()`（整页扁平文本，
   不排除 `.clipkeep-hl`）配纯函数 `resolveHighlight` 现算，一个节点都不改。
   顺手用 `collectTextNodes()` 也能跑，但那个口径是给「拆掉标记之后」用的，拿来做现状报告会把已有标记算漏。
3. **诊断文件是会被贴进 issue 的**：面板上给 60 字预览是为了让用户认出「哪一条」，
   导出时只留编号与长度——把高亮原文和收藏正文搬进文件，等于让用户把自己的读书笔记公开发出去。
   这条边界写成断言：导出内容里不许出现正文子串。
4. **用户选的筛选不许被静默丢掉**：筛到空列表时，第一反应是「自动退回全库」，但那样 chip 还亮着、
   内容却是全库的，比空列表更骗人。现在保留筛选、给一句「这个筛选条件下没有要回顾的」，
   外加一颗常驻的「清除筛选」当出口。进度与每日上限也按筛完的这批算，「只看这一批」才是真的只看这一批。
5. **布局问题只能靠真浏览器量**：jsdom 没有排版，测不出「装不装得下」。设置区接上自检面板后比弹窗还高，
   `.settings` 作为 flex 列里的项，默认最小尺寸等于内容高度，压不下去就被 `body { overflow: hidden }`
   整块裁掉——测试全绿，抓帧一看最后两行根本滚不到。修法是让它自己滚（`min-height:0; overflow-y:auto`），
   守卫只能写成对着 CSS 的静态断言，说明这两行声明为什么不能删。
6. **抓帧管线也要防「白等」**：一帧 = 一次 Chrome 启动（约 50 秒）。`capture.sh` 的清单、
   `driver.js` 的模式、`gen_demo_gif.py` 的帧序三处现在由断言双向咬合，序号还必须从 ① 连续——
   v1.9~v1.10 那四个豆腐块序号就是没人把清单当回事留下的。

### 16. v1.13 就地改、查得准（把断在两截的动作接上，把「无匹配结果」说清）
1. **内联编辑器跟着卡片走，不跟着屏幕走**：`revEdit` 只记「开着哪种编辑」不够，必须同时记 `revEditFor`
   是哪一条。复习卡片会因为打分、换筛选、清除筛选整张换掉，旧卡上打了一半的字留在新卡上，
   等于把上一条的标签塞进这一条——这是会写坏数据的错，不是难看的错。
2. **「改完还是这一条」是承诺，得由状态机兑现**：`clipkeep:update` 回来要重渲染整张卡，
   默认结果就是答案被合回去、用户以为没保存。所以 `revealedFor` 记下哪张卡是开着的，
   重渲染后原样翻开；换卡、切页签才合上。守卫写在测试里：保存后 `.rev-back` 仍然不 hidden。
3. **打字与打分共用一个 document**：复习页的 `1 / 2 / 3` 是全局键位，新加的输入框若不当回事，
   用户敲「1」想打标签数字，卡片已经翻到下一条。输入框内的按键归输入框，这条要用真按键序测试钉住。
4. **上限与筛选的结果必须如实报**：标签超 12 个被夹掉几条就说几条；这条因为改标签被筛出当前筛选组，
   明说「已移出当前筛选（某个标签）」再翻下一条——静默换一条，用户只知道「我刚才改了个标签，卡不见了」。
5. **搜索的诚实边界在空态**：多关键词最难的地方不是匹配，而是搜不中时怎么解释。
   分三种说：哪个词一条都没命中；各词都有命中只是不在同一条里；筛选还开着时补一句
   「（说的是当前筛选剩下的这批）」。本轮审计发现的唯一缺陷就是第三种：带标签筛选时，
   提示把全库里明明存在的词说成「一条都没命中」，用户上一屏刚见过它。
6. **未知前缀当普通文字，不报错也不丢**：用户敲「作者:量子」时，正文里真可能有这几个字。
   报错是在教训人，静默丢掉是在吃用户的输入，只有当普通文字处理两边都不亏。
7. **限过字段的词不许越界涂黄**：`备注:量子` 只在备注里标——正文里也有「量子」却涂黄，
   等于用颜色宣称「正文命中了」，而筛选根本不看正文。高亮的分词必须跟着字段走。
8. **msgid 得含汉字才进覆盖率扫描**：`collectMsgids()` 按汉字筛，纯全角标点（「、」）永远扫不到，
   词典里给它留的条目就成了双向断言都查不出的僵尸。分隔符这类东西做成品语感知的常量，不进词典。
9. **抓帧管线补第四个咬合方向**：`capture.sh` 的帧名必须真是 `driver.js` 里的模式。
   名字打错不报错——驱动静默退回第一帧，PNG 的尺寸、配色、文件大小全都正常，
   只有放大看才发现拍的是列表而不是复习卡片。三个已有方向都会红，唯独这个会「出图成功而内容是错的」。
10. **界面里撞不见的语法等于没做**：字段前缀只写在 README，用户不会去查文档，功能就当没上线。
    搜索框的 `title` 写清「空格分词＝都要命中；`标题:` / `备注:` / `标签:` / `站点:` 限定字段」，
    这条也进覆盖率检查（msgid 含汉字，英文漏翻就红）。
11. **文档承诺也是断言的靶子**：README 从 v1.2 起就写「正文、备注与来源标题里直接标黄」，
    而标题那一行从来没标过——标题参与匹配（`标题:` 筛的就是它）却不涂色，被筛出来的收藏看着像凭空出现。
    本轮选择把色标上（跟着字段规则走，`备注:` 限定的词不许跑到标题上），而不是把话改小。
12. **断言提示之前把异步链跑完**：`send(update)` → `load()` 回读 → `toast()` 三段异步，
    测试里 `click()` 只等 10ms，读到的是上一条提示。这个竞态差点被当成产品缺陷写进 CHANGELOG。

### 17. v1.14 换锚点修复（已完成）

**这一轮只有一件事**：v1.12 的自检面板能告诉你「这页有 3 条高亮标不回来了」，但只能看着。
本轮把那句诊断变成可操作——回原页面重新划一句，锚点就换掉，攒在上面的批注与颜色一个都不动。
搜索前缀补全按约定继续往后放（要先看用户是不是真常用）。

**几条定下来的口径：**
1. **修复走新增的专用写入路径，不放开旧的**。`clipkeep:update` 的白名单是 note / color / title，
   把 `text` 加进去等于让任意页面的任意脚本改写任意一条高亮的正文。
   新那条 `clipkeep:hl-reanchor` 只许换 `text` / `segs` / `title`，其余字段由后台原样保留。
2. **「对得上」用抹平空白后的互相包含，不用全等**。少划一个标点、浏览器多算一个空格，
   都不该把用户挡回去；但互不包含就是换了一句话——这时拒绝比接受诚实得多，
   因为批注会悄悄挂到另一句上。拒绝时把这条的原文说出来，别让人猜。
3. **横幅必须给全话**。第一版把原文截到 60 字显示（复用自检预览那个常量），
   用户照着残缺一句划回来，我们回「已修复」——少掉那一截他从没划过，等于我们把高亮改短了。
   这条是审计时自己抓到的，先写成失败测试再改。
4. **修没修好由页面说了算**。存储写成功不等于这条回得来（页面结构整个换了就还是标不回来），
   所以重放以后数一遍 `marksFor(id)`；是 0 就说「还是定位不回」，不许显示成已修复。
5. **只在来源页修，且页面侧再核一次 URL**。面板里的结果可能已经过期（用户中途跳了页），
   弹窗传来的来源地址取页面自己报上来的那一条——弹窗手里只有 tab 的 URL，不够准；
   取不到就拒，不猜。
6. **不留存储里根本没有的标记**。写库失败时横幅留着让人再划一次；这条已被别处删掉就当场撤横幅，
   留着只会让人对着一句不存在的话继续划。重复 arm 只认最后一次，`Esc` 随时取消，
   切语言时正等着划选就把横幅拆了重建（浮层跟着偏好走，不然英文界面下顶着一句中文）。
7. **提示分三级，不许一句 ✓ 包打**：正文被 2 万字上限砍过说「已截断」；这次划的比原文短说「短一截」；
   两者都没有才说「已修复 ✓」。新建高亮从 v1.9 起就是这个口径，修复写的是同一份数据，没理由换个说法。
8. **抓帧管线的咬合扩到页面侧**。之前只双向核对弹窗侧（`capture.sh` 帧名 ↔ `driver.js` 模式），
   页面帧那一半是漏的：帧名打错时 `web_driver.js` 静默退回默认的 `sel` 模式，
   出的图尺寸配色全对，只有放大看才发现拍的不是横幅。顺带一条：`web.html` 的桩必须真落库，
   桩只回 `{ok:true}` 而不管 `clipkeep:hl-reanchor`，截图会拍到一个空列表。
