# ClipKeep 开源浏览器插件开发与涨星规划

## 项目定位

跨 Chrome、Edge、Safari 的轻量划词收藏插件，纯前端离线运行，无后端无账号。
学生整理网课重点、上班族留存周报素材都能用，主打**一键划词存本地、导出 Markdown、净化网页阅读**。

## 核心功能清单（v1.0 已完成）

1. 划词监听 + 浮动工具条，点击收藏到 `storage.local`。
2. 快速收藏卡片：支持备注、标签。
3. 右键菜单：收藏选中内容 / 净化阅读本页。
4. 极简列表弹窗：展示已存内容、搜索、排序、标签筛选。
5. Markdown 导出：单条 + 批量。
6. 净化阅读模式：移除广告 / 侧边栏 / 导航，只留正文，可收藏全文。
7. 标签分类、深色模式、一键复制单条。

## 核心功能清单（v1.1 已完成）

8. 划词高亮：四色涂色，落盘后可跨标签页同步，重开页面按文本自动重放。
9. 原文批注：粉色高亮 + 悬停显示，点击高亮可改可删。
10. 每日回顾：Leitner 六盒间隔重复（0/1/3/7/21/90 天），待回顾红点徽标。
11. JSON 备份 / 恢复：收藏 + 高亮单文件导出，按 id 幂等合并。
12. 自动化测试：jsdom 直跑真实代码，58 → 132 项断言，`npm test` 一条命令。

## 核心功能清单（v1.10 已完成）

61. 跨节点高亮锚定：一条高亮按文本节点拆成 `segs: [{ t, pre, post }]`，每段带前后各 24 字上下文；
    重放时按段序（后一段必须落在更靠后的节点）逐段定位，再把跨过的正文拼回来与原文核对，
    对不上就换下一处出现重试（封顶 8 次护住长页面），任何一段找不到则整条放弃——宁可不标也不标满页。

    正文被 20000 字上限砍短时锚点跟着砍齐而不是整份作废；DOM 走查摸到 `display:none` 这类
    浏览器划选不认的字时，整份丢掉锚点退回可见正文，不把用户没见过的字写进正文。
63. 跨元素选区的正文不再丢空格：词间的空白节点是正文的一部分（`Hello␠world` 不能存成 `Helloworld`），
    只掐头去尾丢掉纯空白；`splitText(0)` 不再留下空文本节点。
64. 提示跟着能力走：锚定成功不再保留「跨元素可能不显示」的话术，退回整段查找时才说；
    正文被截断时当场报「已高亮（正文超过 20000 字，已截断）」而不是「已高亮 ✓」。

## 技术选型

- **Manifest V3**（Chrome / Edge）+ Safari 16.4+ 适配层。
- 原生 JavaScript，无框架、无构建工具。
- 存储：`chrome.storage.local` / `browser.storage.local`。
- 高亮重放：`Range.surroundContents` + `TreeWalker` 文本匹配（无坐标依赖，抗排版变化）。
- 回顾调度：Leitner 盒 + `due` 时间戳，字段内嵌在收藏项里，天然随备份走。
- UI：手写 CSS，清爽卡片风（避免 MV3 CSP 对 CDN 的限制）。
- 跨浏览器适配：`const API = browser || chrome` 统一入口。
- 测试：jsdom（仅 devDependency，扩展产物零依赖）。

> 再审计一遍：`clipkeep:update` 的 patch 会不会想写什么写什么、超长地址会不会被截成另一个地址、
> 明细渲染有没有上限、回顾卡片的来源是不是每个出口都过了白名单——先写失败测试复现，再修。

**提交记录：** 2026-09-30 三项功能 + 4 类缺陷修复 + 460→618 项断言 + 文档同步，版本号升到 1.6.0。
四条经验：
1. **成对的东西要一起判**：`kind` 与 `image` / `link` 分开洗，就会出现「徽标说是图片、点开没反应」的收藏；
   同一个道理，写入消息的字段白名单也得一条条消息各自覆盖——`updateHighlight` 早就有，
   `updateItem` 却是开放合并，于是改标签能顺手改掉收藏时间和截断标记。审计时「另一处已经做了」是最容易骗过自己的话。
2. **截断不是无害的兜底**：正文超长截断有「已截断」标记兜着，地址截断却是把用户存的东西换成另一个能点开的地址，
   属于静默篡改。同样是上限，语义不同就要分开处理：这里改成不收并给出说明。
3. **格式升级走读侧兼容**：`clipkeep_activity` 从数字变成 `{ n, ids }`，不迁移、不猜类型，
   读写两端统一过 `activityOf()` 一个入口；旧记录照样统计，只是明细那里如实说明「来自旧版本」。
4. **产品决定也要写成断言**：「弹窗不远程加载缩略图」是隐私决定，不是遗漏。
   它现在是一条会失败的测试（列表里 `<img>` 数量必须为 0），下个想加缩略图的人得先改掉这个决定。

### 10. v1.7 批量与键盘（把高频操作从鼠标手里抢回来）
**AI 开发 Prompt：**
> 收藏列表加批量选择与操作：复选框 + 批量条（全选当前筛选结果 / 批量加标签合并去重 / 批量导出 / 批量删除），
> 整批删除共用一个撤销号，一次撤销还原整批；回顾页支持键盘打分（`空格` 看答案、`1 / 2 / 3` 三档）。
> 再审计一遍：弹窗的写操作连点会不会对着已经消失的数据再发一遍、撤销批量删除的提示有没有报真实条数、
> 批量消息的 id 列表有没有过清洗与数量上限、清空全部以后选择里有没有留下幽灵 id——先写失败测试复现，再修。

**提交记录：** 2026-10-01 两项功能 + 3 类缺陷修复 + 618→742 项断言 + 文档同步，版本号升到 1.7.0。
三条经验：
1. **提示说谎比少一个功能更糟**：连点删除时第二条消息对着已经消失的 id 什么也没做，
   弹窗照样弹「已删除，可撤销」。所有会改存储的点击走同一把 `withLock`，
   提示的内容跟着后台返回的真实结果与真实条数走——审计就盯着「这句话在失败时会说什么」。
2. **批量要有单一的撤销单位**：给每条发一个 `tid`，用户点一次「撤销」只回来一条，剩下的照样算丢了。
   一次批量 = 一个 `tid`，回收站按 `tid` 成批还原并返回 `restored`，前端才有实话可说。
3. **键盘是第二条入口，不是复制粘贴**：`空格` / `1 / 2 / 3` 必须复用按钮用的同一份 `revealAnswer()` /
   `gradeCurrent()`，并且要处理「答案没露就不许打分」「输入框里的键归输入框」「长按自动重复只算一次」
   ——这些恰恰是复制一份逻辑最容易漏掉的边界。

### 11. v1.8 找得到（把「翻」变成「筛」，把鼠标操作变成按键）
1. **筛选要按「库实际上有什么」生成**：类型与站点 chip 由当前数据算出来，只有一种类型且只有一个站点时
   整条筛选条不出现；数据变了就剪掉已经不存在的选项——摆一个点不出东西的控件，比没有控件更糟。
2. **筛完的提示必须说人话**：库里明明有货却报「还没有收藏」是提示说谎，改成「筛选后没有结果」。
3. **键盘流复用鼠标那条路**：`x` 勾选取决于 `toggleSelect`、`Enter` 直接点行内的展开按钮，
   不另写一份逻辑；输入控件里的按键归控件，帮助浮层开着时其它按键归浮层。
4. **整条重绘会吃掉焦点**：chip 用 `innerHTML` 重绘后必须把焦点放回原来那个，否则键盘用户从头再 Tab 一遍。

**提交记录：** 2026-10-02 两项功能 + 7 类缺陷修复 + 742→854 项断言 + 文档同步，版本号升到 1.8.0。
三条经验：
1. **「成功」要按真实后果定义**：`delete` 对不在册的 id 返回 `ok` 本身就是在撒谎——它什么都没删、
   也没进回收站，前端据此说的每一句「可撤销」都是空话。写入类消息的成败口径统一成「存储是否真的变了」。
2. **计数要只算真发生的**：撤销整批时 `restored` 把撞 id 没回来的几条也算进去，覆盖失败时照报待写条数——
   数字看着合理，用户却会在这些数字上做出「不用再来一遍」的判断。
3. **成功的提示也要带上不完整**：截断是后台正常完成的一次写入，`ok` 为真，但「已收藏 ✓」并不等于「剪全了」。
   凡是结果与用户预期可能不一致的正常路径（重复、截断、上限），都值得一句明确的话术。

### 12. v1.9 重叠与逐条（让「多标一层」和「误删一条」都不再靠运气）
1. **重叠区间要按边界切开，不是「后者覆盖前者」**：同一段话先标一句、再标包住它的整段是最常见的用法，
   旧写法把区间当互不相交处理，交集那段只剩一层，用户以为两条都在。分段渲染（ outer 边界 + 段内包裹）
   让两条各自可见，代价是一条高亮会拆成多个片段——于是撤销必须按「同一条」而不是「同一个节点」来。
2. **整批撤销不够用**：回收站只有「全回来 / 全不回来」时，误删一条只能连带还原九条，实际等于没有撤销。
   明细 + 逐条恢复才是可操作的粒度，且按钮文案要写清它只管哪一批。
3. **过期口径必须一致**：整批撤销不先清过期，弹窗开着不动就能让早该消失的条目复活——两条路径同一份数据，
   任何一步少做同样的清理，都会变成数据上的矛盾。

**提交记录：** 2026-10-03 两项功能 + 本轮审计 12 类缺陷修复 + 854→985 项断言 + 文档同步，版本号升到 1.9.0。
五条经验：
1. **上限要说舍弃数，成功也要说不完整**：`TAG_MAX = 12` 之外的标签被后台丢弃，`ok` 为真，
   但只报「标签已更新」用户听不出少存了几个。凡是「做了但没全做」的路径都值得一句明确话术。
2. **附属写排在主键之后**：回收站条目 / 打卡计数和主数据是同一次操作的产物，写在主键前面一旦失败，
   就留下「收藏没了、回收站里却躺着一条没删掉的」这种半更新——比整体失败更难被发现。
3. **身份键不能用在写入时现生成的 id**：备份里的非法 id 会被清洗成新的，拿 id 去比「是不是同一条」
   等于每条都是新的，同一份备份导第二次高亮直接翻倍。身份要按内容（地址 + 正文 + 落点时间）认。
4. **承诺的范围要和代码的作用域一致**：确认框写了「高亮批注不受影响」，实现却把整个回收站清空——
   文案改了 `kind`，函数却没跟上。清空类操作一律按类别过滤，别顺手做全量。
5. **做不到的事先说别做**：跨元素选区（选段里带 `<strong>`）刷新后重放不回来，本版没有伪造锚定，
   而是把提示改成「已高亮（跨元素，刷新后可能不显示）」，并把这个已知限制写成断言钉住，真正的锚定留给 v1.10。

### 13. v1.10 跨节点锚定（把上一版「诚实标注的限制」真正消掉）
1. **锚点要带上下文，还要带顺序**：只按文本匹配的话，一句重复出现三次就会标到第一处；分段锚点加上
   「后一段必须落在更靠后的节点」和「跨过的正文拼回来必须等于原文」两道校验，才敢在长页面上下锚。
   校验不过就换下一处出现重试（`ANCHOR_RETRY = 8` 封顶），全部落完仍对不上则整条不标——
   把一条高亮劈成满页，比刷新后看不见更难解释。
2. **锚点必须与正文自洽**：`join(segs.t) === text` 这条不变式一旦破了，重放就会去标别的字。
   所以后台 `cleanSegs` 对不上就整份作废（退回单段整词查找），正文被 `MAX_TEXT` 砍短时锚点跟着砍齐
   而不是作废——截断是正常写入，不该顺手废掉定位能力。
3. **能摸到的字不等于用户选中的字**：真浏览器审计抓到 `display:none` 的文本会被 DOM 走查切进锚点，
   而 Chrome 的 `Selection.toString()` 不认它们——正文里凭空多出一排用户没见过的字。
   jsdom 两边口径一致，这条在测试里复现不出来，只能靠真浏览器跑一遍；守卫是拼不回可见正文就丢掉锚点。
4. **空白是正文，不是排版**：为了「段间拼接正好等于正文」而顺手丢掉空白节点，会把
   `Hello world` 存成 `Helloworld`。只该掐头去尾丢纯空白，中间那个空格得留着。
